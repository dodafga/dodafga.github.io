# 查驗表單產生器（Inspection Suite）

工程查驗文件線上填寫工具。純前端（HTML / CSS / JavaScript），**不需要伺服器、不需要資料庫、不需要安裝任何套件**，直接放上 GitHub Pages 即可使用。

內含四個模式，可在同一頁切換：

| 模式 | 說明 | 輸出格式 |
|------|------|----------|
| 📋 **查驗單** | 工程施工中請驗單，版面沿用 F-24-03 範本（A4 直式、標楷體）。可勾選「附件表單」一起合併輸出。**附件表單的工程名稱／承包商／工地主任／查驗日期／查驗人員／監造人員／墩號／樁號／查驗位置與查驗單共用同一份資料**（附件區塊唯讀顯示，改一次兩邊同步）。 | `.docx` |
| 📷 **查驗相片表** | 工程照片記錄表，每頁 3 張照片，照片尺寸與範本一致（A4 直式）。每一頁都能各自填寫「本頁說明」。 | `.docx` |
| 📊 **查驗紀錄表** | 逐筆新增、累積多筆查驗紀錄，資料自動存在瀏覽器本機。**墩號可多選、樁號依墩號分組跨墩勾選、整墩全選**；墩號與樁號**直接併入「查驗位置」欄位**（不另設獨立欄位），並與進度管控表聯動。 | `.xlsx` |
| 🏗️ **預壘樁進度管控表** | 19 個墩號、121 支樁的施作與查驗進度。**進度以查驗日期為基準**；上方有**墩號彙總**（墩開始時間／整墩結束時間／墩狀態）。可切換「實際施作／查驗日期（新→舊）／墩號順序」三種排序。 | `.xlsx` / `.json` |

## 一、專案結構

```
.
├── index.html              # 首頁（四個模式的切換外殼）
├── .nojekyll               # 告訴 GitHub Pages 不要用 Jekyll 處理（重要）
├── README.md               # 本說明文件
├── assets/
│   ├── jszip.min.js        # 產生 .docx / .xlsx 用的 ZIP 函式庫（四個模式共用）
│   ├── store.js            # 共用資料層：localStorage、墩號聯動、墩彙總、JSON/Excel 匯出
│   └── gdrive.js           # Google Drive 純前端儲存（GIS + Drive API v3，scope=drive.file）
├── settings/               # ⚙ 設定頁（Google Drive 連線狀態 + 使用說明）
│   └── index.html
├── form/                   # 查驗單模式
│   ├── index.html
│   ├── formbuilder.js      # 依範本 XML 產生 Word
│   └── template.docx       # 版面範本（F-24-03）
├── photo/                  # 查驗相片表模式
│   ├── index.html
│   ├── photobuilder.js
│   └── template.docx       # 版面範本
├── log/                    # 查驗紀錄表模式
│   ├── index.html
│   ├── logbuilder.js
│   └── template.xlsx       # 版面範本（標題列深藍底白字粗體置中）
└── progress/               # 預壘樁進度管控表模式
    └── index.html          # 墩號彙總、樁位明細、墩號詳情、匯出/匯入
```

所有資源引用**全部使用相對路徑**（例如 `../assets/jszip.min.js`、`template.docx`），因此放在 GitHub Pages 的任何子路徑下都能正常運作。

## 二、部署到 GitHub Pages

### 方法 A：用 GitHub 網頁介面上傳（最簡單，不用裝 Git）

1. **建立 Repository**
   - 登入 [GitHub](https://github.com/) → 右上角 `+` → **New repository**
   - Repository name 例如 `inspection-suite`
   - 選 **Public**（GitHub Pages 免費版需要公開；Private 需付費方案）
   - **不要**勾選 Add a README file（我們已經有了）
   - 按 **Create repository**

2. **上傳檔案**
   - 進入剛建立的 repository → 點 **Add file** → **Upload files**
   - 把本專案**解壓縮後的所有檔案與資料夾**（`index.html`、`assets/`、`form/`、`photo/`、`log/`、`progress/`、`settings/`、`.nojekyll`、`README.md`）一起拖進去
   - ⚠️ **重點**：要上傳的是**資料夾裡面的內容**，不是外面那層資料夾。上傳後 repository 首頁應該直接看到 `index.html`，而不是 `inspection-suite/index.html`。
   - ⚠️ `.nojekyll` 是隱藏檔，用拖曳上傳時請確認它也在清單中（若看不到，可在檔案總管開啟「顯示隱藏檔案」）。
   - 下方 Commit message 隨便填（例如 `Initial commit`）→ 按 **Commit changes**

3. **開啟 GitHub Pages**
   - 進入 repository → 上方 **Settings** 分頁
   - 左側選單找到 **Pages**
   - **Source** 選 `Deploy from a branch`
   - **Branch** 選 `main`，資料夾選 `/ (root)` → 按 **Save**
   - 等 1～2 分鐘，重新整理這個頁面，上方會出現網址：
     ```
     https://<你的帳號>.github.io/inspection-suite/
     ```
   - 點進去就是首頁，四個模式都能用。

### 方法 B：用 Git 指令上傳

```bash
# 在本專案資料夾內
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<你的帳號>/inspection-suite.git
git push -u origin main
```

推上去之後，再照上面「方法 A 的第 3 步」開啟 GitHub Pages 即可。

### 更新檔案

- **網頁介面**：進入 repository → 點要改的檔案 → 右上角鉛筆圖示編輯 → Commit changes。或再按 **Add file → Upload files** 覆蓋舊檔。
- **Git 指令**：改完檔案後 `git add . && git commit -m "update" && git push`。
- 更新後 GitHub Pages 約 1～2 分鐘生效（瀏覽器若看到舊版，按 `Ctrl + F5` 強制重新整理）。

## 三、使用方式

### 切換模式
開啟首頁後，右上角有五個按鈕：**查驗單 / 查驗相片表 / 查驗紀錄表 / 預壘樁進度 / ⚙ 設定**，點擊即可切換。網址會帶上 `#form`、`#photo`、`#log`、`#progress`，可直接分享特定模式的連結。

### 📋 查驗單
1. 填寫工程名稱、單位位置、查驗日期等欄位。
2. **查驗基本資料**（與附件表單共用）：選查驗人員、監造人員；墩號可多選（chip），樁號依墩號分組加入。
3. 下方逐筆新增「查驗項目」（項目名稱、單位、數量、說明等）。
4. 若要附上附件表單：勾選 **加入附件表單**，展開後填寫（契約項次、項目及說明、單位、查驗數量、監造覆核），可新增／刪除列。**共用欄位在附件區塊以唯讀方式顯示，按「↩ 回查驗單修改」可跳回上方修改。**
5. 按 **下載 Word**，附件表單會另起一頁接在查驗單後面，成為同一份 `.docx`。
6. 表單內容會自動存成草稿，重新整理後仍保留。

### 📷 查驗相片表
1. 設定工程名稱、表頭標題、起始編號。
2. 上傳照片（每頁 3 張），可為每張照片填寫說明。
3. 用 **← 上一頁 / 下一頁 →** 切換頁次，**每一頁都能各自填寫「本頁說明」**，輸入即時反映在預覽。
4. 按 **下載 Word** 輸出 `.docx`。

### 📊 查驗紀錄表
1. 填寫 **查驗日期**（日期選擇器，格式 `yyyy/mm/dd`，可手動輸入）、**查驗人員**（下拉選單）、**監造人員**（下拉選單）。
2. **查驗位置（單一欄位）**：直接填自由文字，例：`PR4-1、PR4-2 橋墩基礎`。
3. **墩號（可多選）**：從下拉選墩號 → 自動加入清單（例：PR4、PR3）。
4. **樁號（依墩分組，可跨墩勾選）**：
   - 樁號下拉依已選墩號分組（`PR4` 群組：PR4-1～PR4-4；`PR3` 群組：PR3-1～PR3-4）。
   - 選一支樁號即自動加入。
   - **整墩全選**：按「PR4 整墩全選（4 支）」一鍵把該墩全部樁號加入。
5. **墩號與樁號會自動併入查驗位置欄**：例如選了 PR4-1、PR4-2 再填「橋墩基礎」，欄位就變成 `PR4-1、PR4-2 橋墩基礎`。**沒有獨立的墩號／樁號欄位**，畫面上也不顯示標籤。
6. 按 **＋ 新增紀錄** 加入下方表格，會自動顯示序號。
7. 每列可**編輯**、可**刪除**。
8. 資料自動存在瀏覽器 **localStorage**，重新整理或下次開啟網頁紀錄還在。
9. 按 **下載 Excel** 輸出 `.xlsx`（標題列深藍底白字粗體置中、欄寬、框線、日期格式皆與範本一致，**共四欄：日期／查驗人員／監造派員／查驗位置**，墩號與樁號已包含在查驗位置內）。
10. 按 **清除全部** 可清空所有紀錄。

> **固定選項**
> - 查驗人員：乘恩、順哲、火木、佩璇
> - 監造人員：振源、旭程、慧欣

### 🏗️ 預壘樁進度管控表

**基本操作**
1. 表格列出 19 個墩號、共 121 支樁，欄位沿用 Excel 原表：墩號、樁號、類型、岸別、預定開始／完成、實際開始／完成、**進度日期**、完成狀態、查驗狀態、查驗日期、備註。
2. **實際開始／實際完成**：直接點日期欄填寫。**完成狀態判定優先順序：已查驗 → 已完成（不論實際日期是否填寫）；未查驗但有實際完成 → 已完成；未查驗但有實際開始 → 施作中；都沒有 → 未施作。**
3. **進度日期（唯讀）**：**以查驗日期為基準** — 該樁有查驗紀錄時，進度日期＝查驗日期（多筆取最新）；沒有查驗才回退實際完成／實際開始。藍色＝依查驗日期，綠色＝依實際日期。
4. **完成狀態**、**查驗狀態**、**查驗日期** 為唯讀，由系統自動判定（查驗狀態由查驗紀錄表聯動）。
5. **備註**：可直接輸入，即時儲存。
6. 上方統計卡即時顯示：全案樁數、已完成、施作中、未施作、已查驗、進度差異（實際－預定）。**進度差異以查驗日期為基準計算**（有進度日期者 － 已到預定完成日者）。
7. 篩選工具列：可按**岸別**（右岸／左岸／復舊）、**完成狀態**、**查驗狀態**篩選，或用搜尋框找墩號／樁號。
8. **排序切換**（工具列最右側下拉）：
   - **排序：實際施作（早→晚）**（預設）— 有填「實際開始」的樁依日期由早到晚排在前面；沒有實際日期的排在後面，再依墩號、樁號排序。
   - **排序：查驗日期（新→舊）** — 已查驗的樁依查驗日期由新到舊排在前面；未查驗的樁排在後面，再依墩號、樁號排序。查驗日期相同時以墩號、樁號為次要排序。
   - **排序：墩號順序** — 回到原本的墩號（PR4→PR3→PR5…）＋樁號順序。
   - 排序與篩選、搜尋可同時使用（先篩選再排序）。
9. **今日開工**：一鍵把「已到預定開始日但尚未開工」的樁設為今日實際開始。
10. **重設進度**：清除所有實際日期與備註（查驗紀錄保留）。

**墩號彙總（表格上方）**
- 每個墩號一列，顯示：墩號、類型、岸別、樁數、已完成、已查驗、**墩開始時間**、**整墩結束時間**、墩狀態。
- **墩開始時間** ＝ 該墩所有樁中最早的實際開始日期；若無實際開始，取最早的查驗日期。
- **整墩結束時間** ＝ 該墩所有樁都完成時，取最晚的實際完成／查驗日期；若還有樁未完成，顯示「**進行中（未完成 N 支）**」。
- 墩狀態：全部完成 → 已完成；有任一樁完成或施作中 → 施作中；都沒有 → 未施作。
- 點墩號可直接開啟該墩詳情面板。

**查看墩號詳情**
- 點表格最左側的**墩號**（藍色粗體），右側會滑出詳情面板，顯示：
  - 基本資料（墩號、樁數、類型、岸別、預定期程、完成／查驗支數）
  - **墩時間彙總**（墩開始時間、整墩結束時間、墩狀態、未完成支數）
  - 查驗狀態與查驗日期
  - **該墩號的所有查驗紀錄**（日期、查驗人員、監造派員、查驗位置、**該筆涵蓋的墩號與樁號清單**）
  - 該墩號下每一支樁的完成與查驗狀態（含進度日期）

**匯出／匯入**
- **匯出 Excel（進度表＋墩號彙總）**：輸出 `.xlsx`，含**兩個工作表** — 「進度管控表」（121 支樁，含進度日期欄）與「墩號彙總」（19 墩，含墩開始時間、整墩結束時間、墩狀態）。
- **匯出 JSON（含查驗紀錄）**：完整備份樁位＋查驗紀錄，**並附 `pierSummary` 墩號彙總**，可跨裝置還原。
- **匯入 JSON**：選擇先前匯出的 JSON 檔，確認後覆蓋目前資料。

## 三之二、查驗紀錄表 ↔ 進度管控表 聯動

兩個頁面共用同一份本機資料（`localStorage` 鍵：`inspection-suite-data-v1`），因此**一邊填、另一邊自動更新**。

### 操作步驟（簡短版）

**① 在查驗紀錄表登記查驗**
1. 切到「查驗紀錄表」。
2. 填查驗日期（例：2026/11/11）、選查驗人員、選監造人員。
3. **墩號下拉選 PR4**（可再加 PR3）。
4. **樁號下拉會依墩分組**，選 PR4-1 再加入 PR4-2 → **查驗位置欄自動變成 `PR4-1、PR4-2`**，再往後補「橋墩基礎」。
5. 按「＋ 新增紀錄」。

**② 進度管控表自動標記**
6. 切到「預壘樁進度」。
7. **只有 PR4-1、PR4-2 兩支**變成「已查驗」，查驗日期顯示 **2026/11/11**；PR4-3、PR4-4 仍為「未查驗」。
8. 上方「已查驗」統計數字同步 +2。

**③ 從進度表回查紀錄**
9. 在進度表點 **PR4** 墩號。
10. 右側面板顯示該墩的查驗紀錄：日期、查驗人員、監造派員、查驗位置，以及**該筆涵蓋的墩號與樁號清單**（PR4、PR3、PR4-1、PR4-2）。

### 聯動規則

| 規則 | 說明 |
|------|------|
| 樁號 → 樁 | 一筆查驗紀錄列出哪幾支樁號，**就只有那幾支**標記為「已查驗」 |
| 舊資料（無樁號清單） | 只有墩號、沒有樁號清單的舊紀錄，視為該墩**全部樁號**已查驗（向後相容） |
| 舊資料（多墩字串） | 舊格式 `pier: "PR4、PR3"` 會自動拆成兩個墩號 |
| 日期一致 | 進度表顯示的查驗日期 = 查驗紀錄的日期，**完全同步** |
| 多筆紀錄 | 同一支樁有多筆紀錄時，以**最新日期**為準 |
| 未指定墩號 | 查驗紀錄的墩號留空時，不影響進度表 |
| 刪除紀錄 | 刪除查驗紀錄後，該樁若無其他紀錄，會回到「未查驗」 |
| 完成狀態 | **已查驗 → 已完成**（不論實際日期）；未查驗但有實際完成 → 已完成；未查驗但有實際開始 → 施作中；都沒有 → 未施作 |
| 進度日期 | **以查驗日期為基準**；沒有查驗才回退實際完成／實際開始 |

> **小提醒**：若在首頁用頁籤切換，切回進度表或紀錄表時會自動重讀資料，不需手動重新整理。若用兩個瀏覽器分頁同時開，切換視窗時也會自動同步。

## 四、常見問題

**Q：下載的檔案打不開或格式跑掉？**
A：請用 Microsoft Word / Excel 開啟。`.docx` / `.xlsx` 是標準 Office 格式，WPS、LibreOffice 亦可。

**Q：換一台電腦，查驗紀錄表的資料不見了？**
A：紀錄存在**該瀏覽器的本機儲存空間**（localStorage），不會跨裝置同步。換裝置前請先按「下載 Excel」備份，或使用 Google Drive 雲端備份（見第六節）。清除瀏覽器資料也會一併清掉紀錄。

**Q：GitHub Pages 顯示 404？**
A：確認 (1) repository 首頁直接看得到 `index.html`（不是被包在子資料夾裡）；(2) Settings → Pages 的 Branch 設為 `main` / `(root)`；(3) 剛設定完請等 1～2 分鐘。

**Q：網頁打開但功能沒反應？**
A：確認 `assets/`、`form/`、`photo/`、`log/`、`progress/`、`settings/` 六個資料夾都有一起上傳，且 `.nojekyll` 存在。

**Q：可以放在自己的網域嗎？**
A：可以。Settings → Pages → Custom domain 填入你的網域，並依 GitHub 指示設定 DNS。

## 六、Google Drive 雲端儲存（純前端）

資料仍以 **localStorage 為主要儲存**，Google Drive 只是備份與跨裝置同步。未授權或斷網時可照常填寫、匯出 Excel。

### 使用方式

1. 開 **⚙ 設定**（首頁右上角，或 `/settings/`）。**Client ID 已內建，不需自行申請或貼上。**
2. 直接按「🔗 連線 Google Drive」→ 選 Google 帳號 → 同意 `drive.file` 權限。
3. 到 `/log/` 或 `/form/`，按 **☁ 存到 Google Drive**；換裝置時按 **⬇ 從 Google Drive 載入**。

### 狀態顯示

頁面上的狀態列會顯示：**未授權 / 連線中 / 已連線 / 同步中 / 同步失敗**，以及**最後同步時間**與失敗原因。
未設定 Client ID 時按存檔會提示「請先完成 Google Drive 設定」並導向設定頁，不會壞掉。
（目前 Client ID 已內建，此提示僅在 `FIXED_CLIENT_ID` 被清空時才會出現。）

### 隱私

`drive.file` 只能存取本程式自己建立的檔案，**看不到雲端硬碟裡的其他任何檔案**，也不能讀取 Gmail、通訊錄或日曆。資料由瀏覽器直連 Google Drive API（HTTPS），沒有中間伺服器。
