# 查驗表單產生器（Inspection Suite）

工程查驗文件線上填寫工具。純前端（HTML / CSS / JavaScript），**不需要伺服器、不需要資料庫、不需要安裝任何套件**，直接放上 GitHub Pages 即可使用。

內含四個模式，可在同一頁切換：

| 模式 | 說明 | 輸出格式 |
|------|------|----------|
| 📋 **查驗單** | 工程施工中請驗單，版面沿用 F-24-03 範本（A4 直式、標楷體）。可勾選「附件表單」一起合併輸出。 | `.docx` |
| 📷 **查驗相片表** | 工程照片記錄表，每頁 3 張照片，照片尺寸與範本一致（A4 直式）。每一頁都能各自填寫「本頁說明」。 | `.docx` |
| 📊 **查驗紀錄表** | 逐筆新增、累積多筆查驗紀錄，資料自動存在瀏覽器本機。**新增「墩號」欄位**，可與進度管控表聯動。 | `.xlsx` |
| 🏗️ **預壘樁進度管控表** | 19 個墩號、121 支樁的施作與查驗進度。可線上填寫實際日期、查看各墩號查驗紀錄。 | `.xlsx` / `.json` |

## 一、專案結構

```
.
├── index.html              # 首頁（四個模式的切換外殼）
├── .nojekyll               # 告訴 GitHub Pages 不要用 Jekyll 處理（重要）
├── README.md               # 本說明文件
├── assets/
│   ├── jszip.min.js        # 產生 .docx / .xlsx 用的 ZIP 函式庫（四個模式共用）
│   └── store.js            # 共用資料層：localStorage、墩號聯動、JSON/Excel 匯出
├── form/                   # 查驗單模式
│   ├── index.html
│   ├── formbuilder.js      # 依範本 XML 產生 Word
│   └── template.docx       # 版面範本（F-24-03）
├── photo/                  # 查驗相片表模式
│   ├── index.html
│   ├── photobuilder.js
│   └── template.docx       # 版面範本
├── log/                    # 查驗紀錄表模式
│   ├── index.html
│   ├── logbuilder.js
│   └── template.xlsx       # 版面範本（標題列深藍底白字粗體置中）
└── progress/               # 預壘樁進度管控表模式
    └── index.html          # 樁位明細、墩號詳情、匯出/匯入
```

所有資源引用**全部使用相對路徑**（例如 `../assets/jszip.min.js`、`template.docx`），因此放在 GitHub Pages 的任何子路徑下都能正常運作。

## 二、部署到 GitHub Pages

### 方法 A：用 GitHub 網頁介面上傳（最簡單，不用裝 Git）

1. **建立 Repository**
   - 登入 [GitHub](https://github.com/) → 右上角 `+` → **New repository**
   - Repository name 例如 `inspection-suite`
   - 選 **Public**（GitHub Pages 免費版需要公開；Private 需付費方案）
   - **不要**勾選 Add a README file（我們已經有了）
   - 按 **Create repository**

2. **上傳檔案**
   - 進入剛建立的 repository → 點 **Add file** → **Upload files**
   - 把本專案**解壓縮後的所有檔案與資料夾**（`index.html`、`assets/`、`form/`、`photo/`、`log/`、`.nojekyll`、`README.md`）一起拖進去
   - ⚠️ **重點**：要上傳的是**資料夾裡面的內容**，不是外面那層資料夾。上傳後 repository 首頁應該直接看到 `index.html`，而不是 `inspection-suite/index.html`。
   - ⚠️ `.nojekyll` 是隱藏檔，用拖曳上傳時請確認它也在清單中（若看不到，可在檔案總管開啟「顯示隱藏檔案」）。
   - 下方 Commit message 隨便填（例如 `Initial commit`）→ 按 **Commit changes**

3. **開啟 GitHub Pages**
   - 進入 repository → 上方 **Settings** 分頁
   - 左側選單找到 **Pages**
   - **Source** 選 `Deploy from a branch`
   - **Branch** 選 `main`，資料夾選 `/ (root)` → 按 **Save**
   - 等 1～2 分鐘，重新整理這個頁面，上方會出現網址：
     ```
     https://<你的帳號>.github.io/inspection-suite/
     ```
   - 點進去就是首頁，三個模式都能用。

### 方法 B：用 Git 指令上傳

```bash
# 在本專案資料夾內
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/<你的帳號>/inspection-suite.git
git push -u origin main
```

推上去之後，再照上面「方法 A 的第 3 步」開啟 GitHub Pages 即可。

### 更新檔案

- **網頁介面**：進入 repository → 點要改的檔案 → 右上角鉛筆圖示編輯 → Commit changes。或再按 **Add file → Upload files** 覆蓋舊檔。
- **Git 指令**：改完檔案後 `git add . && git commit -m "update" && git push`。
- 更新後 GitHub Pages 約 1～2 分鐘生效（瀏覽器若看到舊版，按 `Ctrl + F5` 強制重新整理）。

## 三、使用方式

### 切換模式
開啟首頁後，右上角有四個按鈕：**查驗單 / 查驗相片表 / 查驗紀錄表 / 預壘樁進度**，點擊即可切換。網址會帶上 `#form`、`#photo`、`#log`、`#progress`，可直接分享特定模式的連結。

### 📋 查驗單
1. 填寫工程名稱、單元位置、查驗日期等欄位。
2. 下方逐筆新增「查驗項目」（項目名稱、單位、數量、說明等）。
3. 若要附上附件表單：勾選 **加入附件表單**，展開後填寫（契約項次、項目及說明、單位、查驗數量、監造覆核），可新增／刪除列。
4. 按 **下載 Word**，附件表單會另起一頁接在查驗單後面，成為同一份 `.docx`。

### 📷 查驗相片表
1. 設定工程名稱、表頭標題、起始編號。
2. 上傳照片（每頁 3 張），可為每張照片填寫說明。
3. 用 **← 上一頁 / 下一頁 →** 切換頁次，**每一頁都能各自填寫「本頁說明」**，輸入即時反映在預覽。
4. 按 **下載 Word** 輸出 `.docx`。

### 📊 查驗紀錄表
1. 填寫 **查驗日期**（日期選擇器，格式 `yyyy/mm/dd`，可手動輸入）、**查驗人員**（下拉選單）、**監造人員**（下拉選單）、**查驗位置**。
2. **墩號**（選填）：從下拉選單選擇本次查驗對應的墩號（PR1～PR10、PL1～PL7、PLAT、RC1）。選了之後會自動同步到進度管控表。
3. 按 **新增** 加入下方表格，會自動顯示序號。
4. 每列可**編輯**、可**刪除**。
5. 資料自動存在瀏覽器 **localStorage**，重新整理或下次開啟網頁紀錄還在。
6. 按 **下載 Excel** 輸出 `.xlsx`（標題列深藍底白字粗體置中、欄寬、框線、日期格式皆與範本一致，**含墩號欄**）。
7. 按 **清除全部** 可清空所有紀錄。

> **固定選項**
> - 查驗人員：乘恩、順昔、火木、佩璇
> - 監造人員：振源、旭程、慧欣

### 🏗️ 預壘樁進度管控表

**基本操作**
1. 表格列出 19 個墩號、共 121 支樁，欄位沿用 Excel 原表：墩號、樁號、類型、岸別、預定開始／完成、實際開始／完成、完成狀態、查驗狀態、查驗日期、備註。
2. **實際開始／實際完成**：直接點日期欄填寫。填了實際完成 → 完成狀態自動變「已完成」；只填實際開始 → 自動變「施作中」。
3. **完成狀態**、**查驗狀態**、**查驗日期** 為唯讀，由系統自動判定（查驗狀態由查驗紀錄表聯動）。
4. **備註**：可直接輸入，即時儲存。
5. 上方統計卡即時顯示：全案樁數、已完成、施作中、未施作、已查驗、進度差異（實際－預定）。
6. 篩選工具列：可按**岸別**（右岸／左岸／復舊）、**完成狀態**、**查驗狀態**篩選，或用搜尋框找墩號／樁號。
7. **今日開工**：一鍵把「已到預定開始日但尚未開工」的樁設為今日實際開始。
8. **重設進度**：清除所有實際日期與備註（查驗紀錄保留）。

**查看墩號詳情**
- 點表格最左側的**墩號**（藍色粗體），右側會滑出詳情面板，顯示：
  - 基本資料（墩號、樁數、類型、岸別、預定期程、完成／查驗支數）
  - 查驗狀態與查驗日期
  - **該墩號的所有查驗紀錄**（日期、查驗人員、監造派員、查驗位置）
  - 該墩號下每一支樁的完成與查驗狀態

**匯出／匯入**
- **匯出 Excel（進度表）**：輸出 121 支樁的完整進度表 `.xlsx`。
- **匯出 JSON（含查驗紀錄）**：完整備份樁位＋查驗紀錄，可跨裝置還原。
- **匯入 JSON**：選擇先前匯出的 JSON 檔，確認後覆蓋目前資料。

## 三之二、查驗紀錄表 ↔ 進度管控表 聯動

兩個頁面共用同一份本機資料（`localStorage` 鍵：`inspection-suite-data-v1`），因此**一邊填、另一邊自動更新**。

### 操作步驟（簡短版）

**① 在查驗紀錄表登記查驗**
1. 切到「查驗紀錄表」。
2. 填查驗日期（例：2026/11/11）、選查驗人員、選監造人員、填查驗位置。
3. **在「墩號」下拉選單選 PR4**。
4. 按「＋ 新增紀錄」。

**② 進度管控表自動標記**
5. 切到「預壘樁進度」。
6. PR4 底下 **4 支樁全部變成「已查驗」**，查驗日期顯示 **2026/11/11**。
7. 上方「已查驗」統計數字同步 +4。

**③ 從進度表回查紀錄**
8. 在進度表點 **PR4** 墩號。
9. 右側面板顯示該墩的查驗紀錄：日期、查驗人員、監造派員、查驗位置。

### 聯動規則

| 規則 | 說明 |
|------|------|
| 墩號 → 樁 | 一筆查驗紀錄指定某墩號，該墩號下**所有樁**都標記為「已查驗」 |
| 日期一致 | 進度表顯示的查驗日期 = 查驗紀錄的日期，**完全同步** |
| 多筆紀錄 | 同一墩號有多筆紀錄時，以**最新日期**為準 |
| 未指定墩號 | 查驗紀錄的墩號留空時，不影響進度表 |
| 刪除紀錄 | 刪除查驗紀錄後，該墩號若無其他紀錄，會回到「未查驗」 |
| 完成狀態 | 由實際日期自動推導，與查驗狀態各自獨立 |

> **小提醒**：若在首頁用頁籤切換，切回進度表或紀錄表時會自動重讀資料，不需手動重新整理。若用兩個瀏覽器分頁同時開，切換視窗時也會自動同步。

## 四、常見問題

**Q：下載的檔案打不開或格式跑掉？**
A：請用 Microsoft Word / Excel 開啟。`.docx` / `.xlsx` 是標準 Office 格式，WPS、LibreOffice 亦可。

**Q：換一台電腦，查驗紀錄表的資料不見了？**
A：紀錄存在**該瀏覽器的本機儲存空間**（localStorage），不會跨裝置同步。換裝置前請先按「下載 Excel」備份。清除瀏覽器資料也會一併清掉紀錄。

**Q：GitHub Pages 顯示 404？**
A：確認 (1) repository 首頁直接看得到 `index.html`（不是被包在子資料夾裡）；(2) Settings → Pages 的 Branch 設為 `main` / `(root)`；(3) 剛設定完請等 1～2 分鐘。

**Q：網頁打開但功能沒反應？**
A：確認 `assets/`、`form/`、`photo/`、`log/` 四個資料夾都有一起上傳，且 `.nojekyll` 存在。

**Q：可以放在自己的網域嗎？**
A：可以。Settings → Pages → Custom domain 填入你的網域，並依 GitHub 指示設定 DNS。
